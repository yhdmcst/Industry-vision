# 部署与复现

## 历史模型验证设备

Windows 笔记本；约 32GB 内存；RTX 5060 Laptop 8GB。Python 3.12.14、Ollama 0.35.1、4096 token 部署上下文。模型 /api/ps 证据在基准文件中，不假定所有设备都能达到相同速度。

## 权重来源与安全

官方原模型集合：<https://huggingface.co/collections/XHToken/spark-x25>。

官方 GitHub README：<https://github.com/XHToken/Spark-X2.5>。其模型下载表列出 ModelScope 中国区分发渠道。这里因 Hugging Face 域名解析失败，使用 **XHToken 官方 ModelScope 仓库**；不是从未知第三方重打包权重取样。

1.7B：`models/manifest.json`；4B：`models/manifest-4b.json`。下载脚本固定 revision，校验大小和 SHA-256，失败时不导入。启动脚本再次校验 GGUF，并导入既有 Ollama。原权重与 Ollama blob 副本各占一份磁盘空间。

运行时不是云端 API。客户端拒绝非 loopback 地址，并且只接受项目清单中已核验的 1.7B / 4B 权重 blob；关闭环境代理，FastAPI 仅监听 `127.0.0.1`；Ollama 设置 `OLLAMA_NO_CLOUD=1`。这些配置不等于真实断网测试，提交前应拔网线 / 关闭 Wi-Fi 并复测，记录证据。

## 启动独立 React 工作台

Python 3.12、Node.js 22.12+。依照 README 创建虚拟环境、安装 `requirements-lock.txt`，然后执行：

```sh
npm ci --prefix frontend
npm run build --prefix frontend
python run.py
```

FastAPI 同源提供前端与 `/api`。`run.py` 自动选择可用端口，构建缺失时直接给出构建命令；`--test` 执行测试，`--benchmark` 执行真实模型基准。Windows 可使用 `scripts/start_app.ps1` 后台启动已构建应用。

默认合成 PCB，无需模型与摄像头即可监测、建立事件、人工核验并导出。真实摄像头需在设置中单独连接，先[预检取景](acquisition.md)，再建立正常基线。预检无需基线；显式留存会保存本机像素，可独立标注后发布固定回放数据集。本地视频使用后端可访问的文件路径，不提供上传接口；结束时停止采集并显示错误。

每个服务进程只有一个工作站，**只允许一个 Uvicorn worker**。所有标签页共享采集源、当前基线与监测开关。切换页面或关闭浏览器不会停止采集，请点击“暂停监测”或关闭服务。应用无登录与跨工位隔离，只用于本机，不直接暴露到局域网或公网。

## 前后端开发

在两个终端分别执行：

```sh
python run.py --api-only --port 8501
npm run dev --prefix frontend
```

打开 `http://127.0.0.1:5173`；Vite 将 `/api` 代理至 8501。若后端因端口占用顺延，需同步调整 `frontend/vite.config.ts` 中的代理目标。`npm run preview` 仅预览构建；业务联调使用 Vite dev 或 `run.py`。

前端没有 CDN 与远程字体依赖，构建后运行无需 Node.js 服务。构建与首次依赖安装需要网络或预先准备的缓存，这不等于已经完成断网模型验证。

## 本地 Spark 部署与维护

模型运行在 FastAPI 所在设备，浏览器只发送管理请求。单工作台、单模型并发、4096 token 上下文；只接受官方 Spark 1.7B／4B Q4 权重与 loopback 服务。文本复核不读取图像，也不控制采集设备或生产设备。默认 1.7B，不因单次分类实验改默认规模。

### 页面操作

1. 在“本地模型”选择规模；首次选择保存后，点击“下载并准备模型”。固定来源、版本、大小与 SHA-256 校验通过才发布文件；中断保留片段，可重试续传。损坏的已有正式文件不自动覆盖。
2. 启动服务，再点击“推理自检”。自检核对官方模型身份、真实生成与响应契约，不等于原因识别准确率或工位验收。
3. 切换规模时先准备候选，再点击“验证并切换候选”。自建服务只导入候选别名，保留原服务；外部服务须已导入候选。自检与配置原子保存均通过后才更改选择。失败保留原配置，可用“恢复上一版本”重新校验并切回。
4. 运行策略提供资源优先（回答后释放）、均衡（驻留 10 分钟）与频繁复核（30 分钟），也可自定义 0..60 分钟驻留与 30..600 秒请求等待时限。设定用于下一次推理，不终止在途请求；外部服务可能有自己的资源策略。

随工作台启动和故障自动恢复默认关闭。启用自动启动后，下次应用启动执行现有文件的启动检查，不隐式下载。自动恢复只针对本进程曾成功创建的服务：连续 3 次健康失败后尝试，间隔至少 30 秒，10 分钟内最多 3 次，耗尽后提示人工维护。不能接管外部服务；占用端口时明确失败。不自动重发任何复核。手动停止或取消启动解除恢复意图，手动启动／重启重置恢复预算。

检查、准备和启动可取消；推理自检取消会等待当前 HTTP 请求返回或达到时限，再丢弃结果，不发布候选。切页或关浏览器不取消后台操作。应用退出清理其子进程；只依据当前持有的进程对象，不依据历史 PID 杀进程。复核在途时禁止更改模型、策略或生命周期。

### 平台准备

| 服务端平台 | 项目内准备 | 其他发现方式 | 验证范围 |
| --- | --- | --- | --- |
| macOS Apple Silicon | 固定 Ollama 0.40.2 `ollama-darwin.tgz` | 可指定可执行文件路径 | 本机 M4 真服务与真实推理 |
| Windows x64／arm64 | 固定官方 portable ZIP | PATH、用户安装目录或指定路径 | 下载协议、安全解包与发现逻辑；本轮无 Windows 实机验收 |
| Linux x64／arm64 | 固定官方 tar.zst | PATH 或指定路径 | 下载协议、安全解包与发现逻辑；本轮无 Linux 实机验收 |
| macOS Intel | 页面权重准备需先装官方系统运行时；项目内运行包未提供 | PATH 或指定路径 | 发现逻辑；本轮无 Intel Mac 实机验收 |

后端报告系统与架构，前端不从浏览器推定平台。项目包清单见 `models/runtime-macos.json` 与 `models/runtime-platforms.json`；项目内安装每文件校验并保留许可。系统／指定运行时只检查可执行性与最低客户端版本 0.34.1，不声称包摘要已核验。GPU／Metal／CPU 能力由实际设备和运行时决定。特殊 Linux GPU／JetPack 加速包未纳入自动安装；其他架构可连接已有本地服务。

Intel Mac 可以先安装系统运行时，再使用终端下载权重；其他平台也保留共用实现的 CLI：

```sh
python scripts/install_model_runtime.py
python scripts/download_model.py --size 4b
python scripts/start_model.py --size 4b --check
python scripts/start_model.py --size 4b
```

最后一条在终端持续运行，页面可连接但不能停止。`start_model.ps1` 仅将 PowerShell 参数交给同一 Python 入口。显式路径使用 `--ollama-exe /path/to/ollama`。Mac 首次启动可能由 Ollama 在用户目录创建身份密钥。

### 状态、故障与证据

服务每 5 秒核验身份与元数据，15 秒以上的旧状态不计在线。驻留单独查询，失败保留未知。文件可部署、服务在线、模型驻留、推理成功与答案正确分别判断。每次复核保存实际运行时、官方权重摘要、推理设置，以及已验收的部署版本记录；失败保留原始原因，不产生正常结论。

配置原子保存在数据库旁 `<数据库名>-model.json`，当前选择、运行策略、最近 10 条验收记录和上一版本随应用重启恢复；在线与所有权不从配置恢复。损坏配置保留原文件并说明默认选择。

维护详情折叠服务地址、运行时路径、完整检查结果与原始日志。自建服务日志每文件最多 1 MiB，保留 3 个备份；页面仅读取最近 16 KiB。日志写入失败仍继续排空子进程输出，避免堵塞推理。诊断包包含配置、状态与近期日志，不含图像、人工记录、复核提示词或环境变量；分享前检查本机路径与运行时日志内容。

官方 GGUF 和导入 blob 各占一份空间，4B 至少预留约 6GB，再留运行包、缓存和视觉依赖空间。下载与安装检查当时磁盘容量，不自动删除证据或旧模型。本次不提供任意模型下载、权重删除、训练／微调、远程集群或生产控制。

## M4 容量与工程验收

2026-10-09 本机为 Apple M4、24GiB 统一内存。4B Q4_K_M 官方文件约 2.60GB；Ollama `/api/ps` 报告驻留 2,787,995,810 bytes（约 2.60GiB），上下文 4096。首次结构化调用 10.30 秒，其中加载 2.80 秒、输出 31.93 token/s。公开 PCB 重编码视频上同时执行 CPU PaDiM 与 Spark，三次复核 8.65／7.73／7.74 秒，采集分别增加 12／11／10 帧，状态接口 p95 11.68ms。

**该设备可以部署 4B，并已跑通真实推理闭环。** 当时整机 swap 已占约 22.6GiB，验证期间最高约 23.1GiB，可用内存最低约 4.0GiB；这些是整机读数，不能算成模型独占资源或由本轮造成的增量。驻留字节不是进程峰值或独立显存容量。上述短时实测不证明长期负载、断网、功耗或产线准确率。

验收门槛在调用前固定：三次真实结构化回答，每次 ≤30 秒且视觉采集至少增加一帧；状态接口 p95 ≤1 秒；权重／上下文核验；失败不得增加成功复核，恢复后可重试；人工记录、事件导出与服务重启后的历史一致。当前通过工程门槛；没有原因真值，未通过或宣称语义准确率验收。步骤见[验证记录](verification.md)。

## 可选离线视觉检测

ResNet18／PaDiM 不加入默认工作台运行依赖。安装 `requirements-vision.txt`，用 `scripts/fetch_vision_weights.py` 下载并校验固定权重，按[视觉检测说明](visual-detector.md)准备正常拟合／标定与测试划分，再执行 `scripts/run_padim.py`。实验后可导入 v2 结果包回放，或导出固定配方，在本地模型页连接独立视觉推理进程处理本地视频／摄像头，见[实时接入](vision-validation.md)。模型连接／重载及切回代理均需重新建立工位基线；推理超时须显式重载，不能回退正常结果。安装和权重下载需要网络，推理本身不隐式下载；没有完成真实摄像头吞吐、全设备断网或功耗验证。

## 故障恢复

- 模型连不上：在“本地模型”页检查已保存的端口与模型选择，检查部署文件并启动服务，或对外部终端服务重新核验连接；界面保留规则观测，不生成假模型结果。
- 模型 JSON 错误或 token 截断：显示失败，记录原始问题，不接受结论。不要修改解析器把错误默认成正常。
- 摄像头断开或视频结束：停止监测并显示采集失败。
- 修改数据源 / 基线：旧模型结果无效，不复用。
- 画面接近均匀暗场、纯色或过曝：拒绝基线，先恢复可用取景；不能从不可靠配准猜测机械故障。
- 模型与测量冲突：显示人工核查提示，不修改原始模型答案。无提示也不等于答案正确。
- 资源紧张：优先 1.7B Q4；同一服务仅加载一个模型并发1。不要在8GB显存上强行启用1M上下文。
- 端口占用：应用启动脚本自动换端口；测试脚本默认使用8501，验证时传入实际地址或调整脚本。

## 环境诊断与视觉版本维护

模型页“环境与部署帮助”和 `python scripts/diagnose_workstation.py --endpoint http://127.0.0.1:8501` 读取同一诊断包；不传地址仅检查本机依赖，不推断服务已启动。缺少视觉依赖时按页面指引准备，封存版本在加载时还须核验精确版本。

视觉模型支持同版本修复、回收区卸载／恢复和封存 PaDiM 的受控部署；正在使用的资产禁止修复／卸载，部署不会自动替换默认模型。旧配方、封存统计与最终集消费记录保留。完整目录要求、备份范围与命令见[工作台维护](operations.md)。

## 重测

`pytest` 检查算法边界、来源标记、解析、会话隔离和过期结论。`benchmark.py` 记录真实模型输出；每个场景只调用一次，不能估计准确率。`test_ui.py` 在桌面与手机尺寸上跑浏览器流程。

`test_ui.py --url <实际本地地址> --model-review --model spark-drift:4b-q4` 可验证4B界面。`verify_device.py` 只保留摄像头指标与模型响应、不保存像素；低信号校准失败为预期的保护性拒绝。当前报告不能作为工厂验证。

`compare_thinking.py --input artifacts/benchmark-4b.json --model spark-drift:4b-q4` 复用固定提示词做思考模式对照。当前测试耗尽预算未生成有效结构化答案，不推荐作为默认交互；延迟包含失败调用。

React 浏览器验收使用已安装的 Chrome（或 `--channel msedge` / `chromium`），新证据写入 `artifacts/ui-react/`。本轮已检查桌面与手机截图；团队仍应结合目标工位屏幕与操作习惯验收，历史 PPT 截图不是当前 React 界面。
