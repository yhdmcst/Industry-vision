# 回放评估与版本对比

本模块根据已保存的回放测量和导入标签生成描述性报告。它不触发采样或推理，不修改历史证据。评估对象是上游 OK／NG 判定与规则观测；Spark 解释质量、现场有效性及模型收益仍需独立盲测。

## 使用

1. 在“设置与演示”导入数据集和外部检测结果，建立回放。标签仍只保存在证据中。
2. 执行单帧或连续回放，进入“回放评估”，选择当前或历史会话。
3. 核对进度、检测状态计数、标签覆盖率、混淆矩阵和数据边界，再查看按批次与来源分组的指标。
4. 筛选标签不匹配或检测不可用的样本，点击样本 ID 查看归一化图像。预测与标签分别展示。
5. 选择另一会话进行同条件对比，核对状态、判定和规则变化，导出 JSON 报告。

报告是请求时的证据快照；持续回放产生新测量后需点击“刷新报告”。未运行的评估样本保留在覆盖率分母中，部分回放不会冒充完整结果。页面列出最近 100 个会话中的回放；已知历史会话也可直接通过 API 查询，服务重启不影响历史报告。

## 缺陷标签指标

仅外部检测结果启用缺陷标签分类指标。参考残差为演示代理，不使用它计算缺陷分类匹配率。

v2 异常分数结果与判定置信度分别展示，逐图保留对齐状态；分类指标仍依据成功的布尔判定，失败不转成 OK。两版阈值属于检测器版本，不同异常分数尺度不直接比较。真实 PaDiM 实验入口见[视觉检测](visual-detector.md)。

正类为独立标签 `defect`，负类为 `normal`，预测正类为 `is_ng=true`。`unknown` 为未标注。导入标签是使用者声明，报告将结果称为“标签匹配率”，不等同于经独立验证的产线准确率。

| 指标 | 分母与公式 |
| --- | --- |
| 标签覆盖率 | 有缺陷标签且检测成功的已运行样本 / 所有计划评估样本中有缺陷标签的样本 |
| 标签匹配率 | `(TP + TN) / (TP + TN + FP + FN)` |
| 精确率 | `TP / (TP + FP)` |
| 召回率 | `TP / (TP + FN)` |
| 误报率 | `FP / (FP + TN)` |
| 漏检率 | `FN / (TP + FN)` |

分类指标只使用有缺陷标签且检测成功的样本。缺失、失败、超时不转成 OK 或漏检，分别显示不可用计数；未运行、未标注也单独统计。分母为零输出 `null`，界面显示“—”，不补成 0% 或 100%。成功状态不代表产品合格，置信度不表示合格概率。

## 原因标签指标

行对应导入的 `cause` 标签，列对应规则观测。可分类原因包括 `none`、`optical`、`illumination`、`mechanical`、`product`；原因标签 `unknown` 不参加匹配计算。

规则 `unknown` 记为“证据不足”。预热／检测结果不完整时，规则 `none` 同样记为证据不足，避免将不完整的一致性观测算成正常。已有图像证据支持的光学、光照或机械变化保留原规则分类。

- 原因标签覆盖率：已给出可分类规则观测的样本 / 所有计划评估样本中有原因标签的样本。
- 原因标签匹配率：规则分类与原因标签一致的样本 / 有原因标签且规则已分类的样本。
- 证据不足进入混淆矩阵最后一列与覆盖率分母，排除在已分类匹配率分母之外；未运行另列计数。

规则类别是候选解释，标签也未独立核验。二者匹配不证明已确定根因，产品变化不等同于独立缺陷标签。

## 数据来源与重复检查

报告按批次和三种来源组合分组：合成图像、真实采集且未施加软件扰动、真实采集且施加软件扰动。来源由导入者声明，合成结果包另以 `synthetic_fixture` 标识。

检查覆盖所有计划评估样本，包括尚未运行的样本：

- 归一化图像摘要是否与基线重复。
- 评估集内部是否重复图像。
- 基线和评估是否出现共同批次名称，以及共同来源批次身份。

批次身份优先使用编排的根 `lineage.batch_key`，然后采用采集批次 ID 或声明的 `source_batch_id`；只有名称时保留 `declared:` 标识。相同采集 ID 改名仍被判为共同来源，不同采集 ID 同名只产生名称交叉。普通导入 ID 仍是导入者声明，检查不证明现场独立性。

发现重复时报告提示并保留逐样本记录，不擅自删去样本改变分母。图像不同、批次名不同也不足以证明统计独立；相邻视频帧可能高度相关。报告不自动认定数据集通过盲测隔离，也不提供显著性检验或置信区间。

## 同条件版本对比

数据集 ID、基线样本、评估顺序、窗口、阈值、归一化策略、软件版本和测量源码摘要必须一致。检测器与结果版本允许不同；缺少测量源码摘要或配置不一致时返回不可比较原因，不生成差异计数。

只配对两侧都已运行的样本，按样本 ID 和图像摘要关联。状态变化与规则变化分别计数；OK／NG 变化仅在两侧均为外部结果且检测成功时统计。检测失败后的恢复计入状态变化，不当作判定翻转。含代理时仍可比较规则观测，禁用缺陷判定变化计数。

报告同时保留仅 A、仅 B 的样本数量和共同样本的覆盖、误报、漏检计数。两侧不可用样本可能不同，单独比较匹配率仍会产生偏差，不能据此自动推荐更优版本。检测置信度的语义和校准可能不同，本模块不按分数高低排名。

## API 与复现

```text
GET /api/sessions/{session}/evaluation
GET /api/evaluation/compare?left={sessionA}&right={sessionB}
```

单会话报告包括来源、配置指纹、测量结果摘要、全部计划样本、分组统计及重复检查；对比报告包含两侧报告和共同样本差异。内容摘要排除自身 `report_sha256` 字段。报告按当前评估实现重新计算，并以 `evaluation_source_sha256` 标识评估代码；原始回放、数据集和结果包应一并保留以便追溯。

```sh
python -m pytest tests/test_evaluation.py -q
python scripts/test_evaluation_ui.py --url http://127.0.0.1:8501 --channel chrome
```

浏览器验收只对专用合成工作站执行，使用人为指定的标签与预测验证分母、不可用状态、下载和版本比较；这些标签并非真实缺陷真值。
