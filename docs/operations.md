# 单机工作台维护

工作台保持单 worker、loopback 和单机旁路运行。关闭浏览器不停止采集或模型任务，退出后端会清理本应用创建的进程。

## 状态与操作

本地模型页明确区分配置、周期连接／驻留探测与最近文件／推理检查。设备状态来自后端电脑。常用操作和下一步建议位于主屏，日志、连接设置及维护记录折叠显示。

模型维护任务有独立编号、对象、阶段、开始／结束时间和结果。运行中可取消的任务先进入取消状态，等待实际工作结束才标记取消；完成、失败和取消均保留。重启后未结束的任务标记中断，不自动重发。页面显示最近 20 条，数据库保留全部记录。任务结果保存失败单独提示，不把服务实际变化伪装为未发生。

状态接口支持 `history_token`：历史未变化时省略曲线数据，首次请求或变化后返回完整当前窗口。事件列表仅在会话或事件版本变化后刷新。提交请求期间仍读取状态；旧请求响应不会覆盖较新的状态。读请求超时为 15 秒，写请求为 90 秒；浏览器超时不代表后端任务取消，检查状态后再决定重试。

## 会话证据备份与恢复

设置页显示证据数据库／WAL 占用、会话与记录数，支持主动下载 SQLite 快照。快照包含提交时一致的会话图像、指标、事件、复核／人工记录和模型维护任务，不自动清理历史证据。生成备份不持采集锁；使用 SQLite 在线备份协议和完整性检查，避免直接复制活动数据库时遗漏 WAL。

会话 SQLite 快照不包含模型权重、受管数据集、采集草稿、研究报告目录或数据库旁的模型部署配置。完整受管数据可使用下述工作空间备份；外部依赖仍须单独保留。

恢复只写入**不存在的新数据库路径**，保留源备份和原工作台：

```bash
python scripts/restore_evidence.py --source /path/to/spark-evidence.sqlite --destination /path/to/restored/evidence.db
python run.py --database /path/to/restored/evidence.db --port 8502
```

恢复检查数据库完整性、证据表和 JSON 格式。新工作台可读取历史会话，部署状态重新探测，当前采集和基线重新建立。浏览器页不提供覆盖当前数据库的恢复动作。

## 历史查询与保留

复核页按 50 条分页，以事件 ID 游标向前读取；会话可加载更早记录。搜索编号和变化类型、待复核／已记录筛选在数据库执行。人工记录、生命周期、模型响应与错误按关联事件直接查询，不受最近 10000 条限制；事件列表不读取冻结图像。会话导出包含全部记录，回放结果不截断。

设置页可预览保留范围：只归档截止日期前结束的会话，始终保留当前会话和指定数量的最近会话。确认后在 SQLite 写事务内重验范围，将全部记录连同原 ID 保存为 `archives/<编号>.sqlite`，完整性和逐会话内容核验通过、归档落盘后才释放活动数据库记录。预览过期、写盘或校验失败不删除原证据；已验证归档在后续失败时保留。模型操作记录、样本和模型目录不清理。

归档仍在本机占用空间，可下载并转存到其他介质；本页不删除归档。恢复归档使用 `restore_evidence.py` 写入新数据库，再启动独立工作台查看。活动数据库的空页可复用，也可在暂停状态主动回收未使用空间；这一动作不删除记录。

## 工作空间备份

ZIP 备份包含在线 SQLite 快照、数据库旁的 `datasets/`、`acquisition/`、`inspection-results/`、`review-studies/`、视觉资产、模型部署 JSON 及归档。逐文件记录 SHA-256 和大小，备份前要求暂停采集并结束加载、复核与模型任务；期间拒绝新的写操作，不持工作站锁复制文件，状态可继续读取。检测到受管文件变化时不发布。单次上限 50000 个文件、20 GiB，不跟随符号链接。

这是**受管工作空间**备份，非整个项目／设备备份。源码、Python／Node 依赖、官方语言模型 GGUF 缓存、Ollama 运行时与驻留库、外部原始数据／视频、进程 PID、日志和浏览器草稿不包含。部署到另一设备须另行准备运行时与语言模型缓存，重新检查配置内的本机路径。

```bash
python scripts/restore_workspace.py --source /path/to/spark-workspace.zip --destination /path/to/new-workspace
python run.py --database /path/to/new-workspace/evidence.db --port 8502
```

恢复仅创建不存在的新目录，拒绝重复／越界／链接路径，逐文件验证摘要和数据库完整性。保留原数据库文件名，模型自动启动和恢复策略关闭；视觉配置仍需显式加载。恢复记录保留原清单与调整说明，原 ZIP 不修改。恢复后需重新建立当前基线。

## 模型资产

复核模型资产目录列出两种受支持的官方规模、固定版本、用途、量化方式、文件大小和最近校验。候选准备与当前选择独立，检查按模型保存。文件大小或修改时间变化后提示重新检查；这些快速状态不代替 SHA-256，启动和导入仍执行完整身份检查。驻留大小与加速内存由运行时报告，不推断显卡型号或性能。

视觉模型可登记 `scripts/export_vision_model.py` 导出的原有 PaDiM 配方，或通过“从研发封存协议登记”导出并登记下述封存版本。完整校验后复制到数据库旁 `<数据库文件名>-vision-models/`。最多登记 50 个活动版本，同一配方幂等登记，不覆盖已有资产；失败不发布半成品。目录缺失、文件变化或方法不兼容保持可见，加载时重新验证配方和全部摘要。

页面选择已登记版本并设置单帧时限，支持重载、停用以及恢复最近保存的配置。配置历史在模型加载校验通过后保存，表示已准备好的配置；实际运行以实时状态为准。重启不自动加载，恢复配置需重新创建视觉进程；不能借历史记录假装模型在线。切换、重载与停用须暂停采集、退出回放并结束在途复核，成功启用后清空基线，原证据保留。候选加载失败不会停止原模型。

视觉资产目录和模型部署 JSON 包含在工作空间 ZIP 内，不在会话 SQLite 快照内。登记原目录保持原样；不提供任意架构导入、训练或自动重建损坏统计。

### 修复、卸载与恢复

同版本修复必须提供完整且摘要一致的部署配方，复制后再次校验，不允许改阈值或模型身份。受损目录保存到 `repair-backups/`；配置发布失败恢复原目录。正在使用的版本禁止修复或卸载，请先停用或切换。

卸载先预览版本、大小与当前证据库引用数，确认后从可选目录移除，文件移到 `retired/`，历史证据与原导入目录保留。旧保存配置中的已卸载版本不再可恢复加载。回收区最多 500 个版本，恢复重新验证身份和兼容性，不自动启动模型；缺失／损坏的回收文件明确失败。回收及修复副本仍占用磁盘，不宣称卸载释放了物理空间，也不自动删除用户文件。

### 研发封存协议部署

原研发 `frozen/recipe.json` 与实时配方不是同一协议。部署适配器只支持封存 PaDiM、对齐 PaDiM、对齐 ROI 和对应的固定收缩统计；patch 记忆及任意模型架构拒绝。需完整协议目录（`frozen/`、`freeze-receipt.json`、`split.json`、`validation-selection.json`）和官方 ResNet18 权重：

```bash
python scripts/export_release_model.py --protocol /path/to/release-protocol --weights /path/to/resnet18-f37072fd.pth --output /path/to/new-deployment
```

页面使用相同导出器与资产登记器。新部署协议为 v2 `frozen-padim-v1`，独立记录适配器摘要、原封存身份、方法及文件清单。原阈值、统计、ROI、源码和回执逐文件保留；校验原方法／政策／权重／验证选择及分区摘要，加载再检查冻结依赖版本。适配过程不拟合、不标定、不读最终图像、不重写已消费记录，也不把部署可用等同于效果通过。旧部署配方与封存包不修改。

可选真实接口检查用已观察的拟合参考图，比较直接推理与独立进程响应，不能作为新的效果证据：

```bash
python scripts/check_visual_deployment.py --model /path/to/deployment --output /path/to/new-interface-check.json
```

### 共用诊断

模型页“环境与部署帮助”展示后端设备、实际包版本、官方运行时入口和视觉依赖准备命令。安装记录不证明设备加速或真实推理可用。`/api/diagnostics` 和终端共用工作台诊断包；不包含图像、人工记录、复核提示词或环境变量，分享前检查路径和日志。

```bash
python scripts/diagnose_workstation.py --endpoint http://127.0.0.1:8501 --output /path/to/new-diagnostics.json
python scripts/diagnose_workstation.py
```

无地址时仅输出离线环境检查，运行状态标为未知；有地址仅允许 loopback，通过 API 读取当前状态，不启动或接管任何服务。

## 自动工程检查

GitHub Actions 使用 Python 3.12 和锁定依赖执行 macOS、Windows、Linux 后端功能检查；Node 22 执行 React 构建和格式检查。可选视觉依赖、浏览器、真实模型和设备不由这组 CI 验证，跨平台 CI 通过也不等于三平台真实部署通过。
