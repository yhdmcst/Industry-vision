# 跨批次数据集编排

从采集批次与已导入的固定数据集中选择样本，分别指定参考基线和评估用途，发布为新的固定数据集。原图像、采集时间、批次、来源、软件扰动与独立标签保留，不修改来源草稿或已有版本；发布不切换工作站会话。入口为“设置与演示 → 跨批次数据集编排”。

## 操作

1. 输入编排数据集名称与划分说明。
2. 选择采集批次或固定数据集，指定加入用途。逐个加入，或加入来源中原有的参考／评估组；可切换来源继续选择。
3. 查看来源图像与已选列表，调整用途或移除样本。总数最多 500，必须包含 10–100 个参考和至少 1 个评估样本。参考必须通过取景质量门，不含缺陷、异常原因标签或软件扰动。
4. 点击“检查编排”，查看批次交叉、参考／评估像素重复、评估内部重复、缺失标签及合成／软件扰动提示。
5. 点击“发布编排数据集”，在“样本管理与回放”选择新版本，建立回放。外部质检结果须针对新数据集 ID 与样本摘要重新生成或导入，不自动转移旧结果包。

选择保存在当前页面，刷新或离开页面会清空未发布的选择。源记录有修改时应刷新来源并重新检查；已有发布版本保持不变。发布成功后列表随工作站 revision 刷新，也可手动刷新。

## 身份与检查边界

采集样本按固定采集批次 ID 关联，不以显示名称决定是否为同一批次。不同采集 ID 即使同名也分别保留；改显示名称不能让同一来源批次变成独立批次。

固定数据集样本优先保留已有 `lineage`，采集发布版本可通过其 `capture_batch_id` 回溯原采集样本。再次编排保存根来源身份，同一个原始样本不能从不同版本重复加入。只提供导入批次名称的来源仍属于导入者声明；公开数据的官方 train/test 划分不自动等同于工厂采集批次。批次名称交叉与固定身份交叉分别记录，不通过重新命名消除真实来源关联。

重复像素和来源交叉产生明确提示，不自动删除样本改变分母。操作者可以发布含这些提示的数据用于工程复现，但不能据此宣称完成盲测、统计独立或现场验证。真实缺陷标签仍是操作者／数据发布者提供的独立注释，整体排除在模型快照之外。

发布前检查返回内容摘要，包含编排配置、源标签与元数据、原始身份和当前图像摘要。发布时重新读取并校验全部来源；检查后标签、选择、名称或说明变化将拒绝发布，必须重新检查。图像被修改且摘要不符同样拒绝。进程内工作站锁串行保护草稿操作与发布；应用仍只支持本机单 worker。

## 存储与 API

新版本沿用 `datasets/` 下的内容寻址存储。每个样本额外保留 `lineage`：根来源类型、来源 ID、原样本 ID 与批次关联键。它参加数据集摘要，随历史回放导出保留，不进入模型输入。编排 ID 在来源与样本身份上确定；相同编排重复发布复用版本，修改来源标签后发布生成对应版本。

```json
{
  "name": "工位 A · 批次隔离验证",
  "description": "参考与评估来自不同采集批次",
  "selections": [
    {"kind": "capture", "source_id": "32位采集批次ID", "sample_id": "原样本ID", "split": "baseline"},
    {"kind": "dataset", "source_id": "64位数据集ID", "sample_id": "原样本ID", "split": "evaluation"}
  ]
}
```

以上仅示意两条选择，实际请求须符合完整分组数量要求。调用 `POST /api/composition/preflight` 取得 `checked_sha256`，将其加入同一配置后调用 `POST /api/composition/publish`。不接受不存在的来源、重复身份、坏图像或不合格参考；失败不发布部分数据集。临时文件随失败清理。原子目录发布不等于已经验证断电耐久性。

```sh
python -m pytest tests/test_composition.py tests/test_evaluation.py -q
python scripts/test_composition_ui.py --url http://127.0.0.1:8501 --channel chrome
```

浏览器验收使用专用合成工作站，默认报告位于 `artifacts/ui-composition/`。公开数据验证范围见[公开数据实验](public-data.md)。
