# 基线与告警可靠性

Spark Guard 将规则观测、告警周期和人工核验分别记录。告警只用于提示复核，不控制生产设备；规则恢复不等于确认产品合格。

## 基线发布

建立基线会暂停采集，并在独立候选检测器中验证 10–100 个参考样本。每帧必须是同尺寸的 `uint8` BGR 图像，指标有限，满足 `10 < 平均亮度 < 245` 和 `对比度 ≥ 1`；外部检测结果须逐样本对齐且全部成功。任一帧拒绝则整批不发布，不用平均指标掩盖坏帧。

候选图像、检测统计和 PNG 编码全部成功后，新的 `baseline` 与旧告警的终止记录在同一个 SQLite 事务中保存，再替换运行状态。失败保留旧基线、版本、窗口、图像和告警周期。拒绝原因、有效样本数和样本序号通过 `baseline_attempt` 展示，并尽可能保存为 `baseline_rejected`；存储故障会明确提示记录无法保存。

成功重建会递增基线版本，清空当前窗口并重新预热。清空基线或切换采集源同样结束旧周期，历史事件与人工记录继续保留。采集设备及视频的读取位置无法回滚：重试会读取后续帧；固定回放则使用清单中固定的参考图像。

这些门限只排除明显不可用的取景，不验证产品正常、基线稳定性或现场适用性。稳定但已失焦的图像仍可能通过，参考样本与工况需操作员确认。

## 告警周期

| 当前观测 | 行为 |
| --- | --- |
| 首次规则异常或检测缺失／失败／超时 | 立即冻结事件并开启周期，不等待窗口预热 |
| 同一周期持续异常或异常类型改变 | 保留同一个自动事件；首次出现的新异常类型或不可用状态保存新增证据 |
| 无规则异常，但检测窗口不完整或少于 10 帧 | 标记恢复证据不足，恢复计数归零 |
| 完整检测窗口内无规则异常 | 连续计数，达到恢复帧数后保存恢复证据 |
| 采集失败 | 暂停采集，保留最后成功测量，恢复计数归零并明确数据不可用 |
| 基线／采集源／回放切换 | 保存周期终止原因，不记为异常恢复 |

恢复默认需要 **连续 3 帧**；`config/system_config.yaml` 的 `monitoring.alert_recovery_samples` 可设为 1–100 的整数，修改后重启服务。恢复判断要求整个滑动窗口没有不可用检测结果，并满足现有规则。因此移除软件扰动后，窗口中的旧异常仍可能延迟恢复；帧数也不等于固定秒数。

告警可处于预热、持续、恢复确认、恢复证据不足、规则恢复、未触发规则或采集不可用状态。`GET /api/state` 返回当前 `alert`，成功帧中保留当时的 `alert` 快照。关联信息包括事件 ID、基线版本、首次／最近异常帧、异常类型和不可用状态；软件扰动标签与独立样本标签不进入模型快照。

每次成功测量的帧与对应事件新增／恢复证据在同一事务内保存。保存失败不会留下半条事件或虚假的恢复状态，会暂停采集、回滚未发布状态并清空检测窗口以重新预热。如果错误记录也写不进去，界面仍明确显示保存失败。

## 历史证据

- `incident`：首次异常的冻结图像与测量；人工标记独立保存，不取代自动周期的主事件。
- `incident_updated`：周期内首次出现的新异常类型或缺失／失败／超时状态，包含测量与检测原始结果。连续重复同类异常仍在逐帧记录中保留。
- `incident_recovered`：关联事件、原基线版本、恢复帧、连续计数、完整窗口与测量快照。
- `incident_closed`：因基线、采集源或回放切换终止周期。终止不是恢复，也不代替人工核验。
- `capture_error`：采集／处理／保存错误及当时告警状态，相同连续错误去重；存储不可用时仅能保留运行状态中的错误提示。

事件列表和详情分别展示周期状态及人工核验结论。已保存的恢复／终止记录可在服务重启后读取；只有内存中的活跃周期不会自动恢复运行，缺少恢复记录的历史事件显示“无恢复记录”。不能从缺少记录推断正常。证据导出包含新增、恢复和终止记录，首次事件保持不变。

## 验证

```sh
python -m pytest tests/test_reliability.py tests/test_api.py tests/test_incidents.py tests/test_inspection_results.py -q
python scripts/test_reliability_ui.py --url http://127.0.0.1:8501 --channel chrome
```

浏览器脚本会操作当前工作站，仅对专用合成实例执行；使用合成 PCB、生成视频和脚本检测结果，截图及 JSON 写入 `artifacts/ui-reliability/`。验证范围包括质量门失败保留旧基线、告警去重、恢复确认、证据导出、检测不可用和手机布局。SQLite 故障使用测试触发器注入，不代表真实断电或磁盘耐久性测试。实际执行记录见[验证说明](verification.md)。
